# Compositor abstraction and the Niri backend

Baseline: niri 26.04 (2026-04-25). All niri commands here assume `niri msg`
and `$NIRI_SOCKET` are present in the session.

## The interface (current)

`/home/xscriptor/Documents/repos/xscriptor/equisdots/shell/core/Compositor.qml`
is a singleton with exactly seven members:

| Member | Kind | Semantics |
| --- | --- | --- |
| `workspacesCommand` | command array | A long-running daemon. It writes JSON to `<runDir>/workspaces/workspaces.json`; the bar cats that file (see `shell/ui/bar/Bar.qml` `wsDaemon`/`wsReader`). Each entry: `{ id, state: "active"\|"occupied"\|"empty", tooltip, classes }`. |
| `keyboardCommand` | command array | One-shot poll. Prints the active keyboard layout name (e.g. `English (US)`). |
| `focusCommand` | command array | One-shot poll. Prints `class\ntitle` of the focused window, or nothing. |
| `setWindowBorders(activeSpec, inactiveSpec)` | function | Push live window border colors. Spec `{ hex, alpha, second, angle }` (see `shell/ui/bar/Colors.qml` `borderSpec`). |
| `switchWorkspace(name)` | function | Focus a workspace by identifier. |
| `cycleKeyboardLayout()` | function | Advance to the next configured keyboard layout. |
| `backend` | property | The selected implementation object. Currently `Hyprland {}`. |

The contract is intentionally output-shape preserving: a backend may compute
values however it likes as long as the shapes above hold. `Hyprland.qml` (49
lines) is the only implementation.

## Member mapping: Hyprland vs niri

| Member | Hyprland | niri |
| --- | --- | --- |
| `workspacesCommand` | `scripts/workspaces.sh` daemon writing JSON via `hyprctl workspaces/clients -j` and `.socket2.sock` | A daemon script that maintains the same JSON file from `niri msg --json workspaces` + `niri msg --json windows`, updated from `niri msg --json event-stream`. niri workspaces are dynamic, so the pill list is derived, not fixed `1..N`. |
| `keyboardCommand` | `hyprctl devices -j` -> `.keyboards[].active_keymap` | `niri msg --json keyboard-layouts` -> `.names[.current_idx]` |
| `focusCommand` | `hyprctl activewindow -j` -> `.class`, `.title` | `niri msg --json focused-window` -> `.app_id`, `.title` |
| `setWindowBorders` | `hyprctl eval 'hl.config({ general = { col = { ... } } })'` | Write the border block into an included KDL file, then reload (see below). |
| `switchWorkspace(name)` | `hyprctl eval 'hl.dispatch(hl.dsp.focus({ workspace = <n> }))'`, plus `qs_manager.sh` unified-desktop logic | `niri msg action focus-workspace <index\|name>`; the unified-desktop helper is redesigned (see risks). |
| `cycleKeyboardLayout()` | `hyprctl switchxkblayout main next` | `niri msg action switch-layout next` |

## `setWindowBorders`: write KDL and reload

niri has no `hyprctl eval`. Window borders and the focus ring live in the
top-level `layout {}` section, and `layout` deep-merges across `include`s, so a
generated include is the natural target.

Create `~/.config/niri/modules/equisdots-borders.kdl`:

```kdl
// Auto-generated by the compositor backend. Do not edit manually.
layout {
    border {
        on
        width 2
        active-color "#fc618dee"
        inactive-color "#69676caa"
    }
    focus-ring {
        // The shell's "active border" concept maps to the niri border; set the
        // ring off so there is a single active indicator, matching Hyprland.
        off
    }
}
```

Mapping from the `{ hex, alpha, second, angle }` spec:

- Solid (`second` empty): `active-color "#" + hex + alpha`.
- Gradient (`second` present): `active-gradient from="#"+hex+alpha to="#"+second+alpha angle=<angle>` (niri gradients are CSS-like; `relative-to="workspace-view"` is available if the equisdots look needs it).
- Inactive spec uses `inactive-color` / `inactive-gradient`.

Then reload. Because every included file is watched, saving already triggers a
reload; `niri msg action load-config-file` forces it deterministically:

```sh
niri msg action load-config-file
```

Unlike Hyprland's `hl.config` auto-reload (which visibly restarts windows on
Lua writes), a niri config reload for `layout` is a settings merge and does not
restart clients. This makes the "preview live while dragging, persist on close"
pattern from `HyprEffects.qml` unnecessary for borders: a single KDL write per
change is acceptable, though debouncing remains good practice.

The load-time fallback `hyprland/config/hypr/colors.lua` is replaced by the
same generated include plus, optionally, a `colors.kdl` module that is written
by the installer from `settings.json -> bar.palette`. niri KDL cannot read JSON
at parse time, so the first border push (or a `dots install` step) must generate
the initial values.

## `switchWorkspace`, `cycleKeyboardLayout`, focus

- Focus a workspace: `niri msg action focus-workspace <index-or-name>`. The
  shell passes a `wsName`; niri accepts either an `idx` or a workspace `name`.
- Move a window: `niri msg action move-window-to-workspace <index|name>
  focus=false` (or `move-column-to-workspace`).
- Keyboard layout: `niri msg action switch-layout next` (also `prev`,
  `<index>`). Layout list comes from `niri msg --json keyboard-layouts`.
- Focused window: `niri msg --json focused-window | jq -r 'select(. != null) |
  "\(.app_id)\n\(.title // "")"'`.

## Backend selection

`XDG_CURRENT_DESKTOP` is set by the session (`niri` sets a value containing
`niri`; the Hyprland `env.lua` sets `XDG_CURRENT_DESKTOP=Hyprland`). Select on
it inside `Compositor.qml` so widgets never branch:

```qml
pragma Singleton
import QtQuick
import Quickshell
import "compositors"

QtObject {
    id: root

    readonly property string desktop: (Quickshell.env("XDG_CURRENT_DESKTOP") || "").toLowerCase()

    // Both instances exist; only the selected one is read. QtObject instances
    // are cheap and this avoids a Loader's async gap in a singleton.
    readonly property Hyprland _hypr: Hyprland {}
    readonly property Niri     _niri: Niri {}

    readonly property var backend: root.desktop.indexOf("niri") !== -1 ? root._niri : root._hypr

    readonly property var workspacesCommand: root.backend.workspacesCommand
    readonly property var keyboardCommand: root.backend.keyboardCommand
    readonly property var focusCommand: root.backend.focusCommand

    function setWindowBorders(a, i) { root.backend.setWindowBorders(a, i); }
    function switchWorkspace(name) { root.backend.switchWorkspace(name); }
    function cycleKeyboardLayout() { root.backend.cycleKeyboardLayout(); }
}
```

Note: `Quickshell.env()` reads the process environment. If the shell is ever
started without `XDG_CURRENT_DESKTOP`, fall back to probing (e.g.
`command -v niri && [ -n "$NIRI_SOCKET" ]`) or a `settings.json` override. Add
`compositor` to `settings.json` as an escape hatch only if probing proves
unreliable.

## Proposed `shell/core/compositors/Niri.qml`

Uses real niri 26.04 commands. The workspace daemon is a shell script (reusing
the existing `qs_ensure_cache`/run-dir contract so `Bar.qml` needs no change);
`switchWorkspace` routes through `qs_manager.sh` for parity with Hyprland.

```qml
// ═══════════════════════════════════════════════════════════════════════════
// shell · core/compositors — niri backend
//
// niri implementation of the Compositor surface. Output shapes match
// Hyprland.qml so widgets keep working unchanged.
// ═══════════════════════════════════════════════════════════════════════════
import QtQuick
import Quickshell

QtObject {
    id: backend

    // Long-running daemon writing <runDir>/workspaces/workspaces.json from
    // `niri msg --json event-stream` (same file the bar already reads).
    readonly property var workspacesCommand:
        ["bash", "-c", "~/.config/hypr/scripts/quickshell/core/scripts/niri-workspaces.sh"]

    // One-shot: active keyboard layout name.
    readonly property var keyboardCommand:
        ["bash", "-c",
         "niri msg --json keyboard-layouts 2>/dev/null | jq -r '.names[.current_idx] // empty'"]

    // One-shot: "app_id\ntitle" of the focused window.
    readonly property var focusCommand:
        ["bash", "-c",
         "niri msg --json focused-window 2>/dev/null | " +
         "jq -r 'if (.app_id != null and .app_id != \"\") then (.app_id + \"\\n\" + (.title // \"\")) else empty end' 2>/dev/null"]

    // ── window borders: write a generated KDL include, then reload ──────────
    // spec = { hex, alpha, second, angle } (Colors.borderSpec).
    function kdlColor(prefix, spec) {
        const alpha = (spec && spec.alpha) ? String(spec.alpha) : "ee";
        const hex = String((spec && spec.hex) || "#ffffff").replace("#", "");
        const second = (spec && spec.second) ? String(spec.second).replace("#", "") : "";
        if (/^[0-9a-fA-F]{6}$/.test(second)) {
            const angle = Math.round(Number((spec && spec.angle) || 45));
            return prefix + "-gradient from=\"#" + hex + alpha + "\" to=\"#" + second
                 + alpha + "\" angle=" + angle;
        }
        return prefix + "-color \"#" + hex + alpha + "\"";
    }

    function setWindowBorders(activeSpec, inactiveSpec) {
        const kdl =
            "// Auto-generated. Do not edit.\n" +
            "layout {\n" +
            "    border {\n" +
            "        on\n" +
            "        width 2\n" +
            "        " + kdlColor("active", activeSpec) + "\n" +
            "        " + kdlColor("inactive", inactiveSpec) + "\n" +
            "    }\n" +
            "    focus-ring { off }\n" +
            "}\n";
        // Atomic write + reload. $HOME is expanded by bash.
        const script =
            "mkdir -p \"$HOME/.config/niri/modules\" && " +
            "tmp=$(mktemp \"$HOME/.config/niri/modules/.borders.XXXXXX\") && " +
            "cat > \"$tmp\" <<'KDL'\n" + kdl + "KDL\n" +
            "mv \"$tmp\" \"$HOME/.config/niri/modules/equisdots-borders.kdl\" && " +
            "niri msg action load-config-file >/dev/null 2>&1";
        Quickshell.execDetached(["bash", "-c", script]);
    }

    function switchWorkspace(name) {
        // qs_manager.sh keeps the unified-desktop / popup-close behavior; its
        // niri branch calls `niri msg action focus-workspace`.
        Quickshell.execDetached(["bash", "-c",
            "~/.config/hypr/scripts/qs_manager.sh " + name]);
    }

    function cycleKeyboardLayout() {
        Quickshell.execDetached(["niri", "msg", "action", "switch-layout", "next"]);
    }
}
```

### The workspace daemon (`niri-workspaces.sh`)

It must reproduce the JSON shape and the run-dir path (`qs_ensure_cache
"workspaces"`). Skeleton logic:

```bash
#!/usr/bin/env bash
set -u
# caching.sh lives in ~/.config/hypr/scripts; this script lives in
# ~/.config/hypr/scripts/quickshell/core/scripts.
source "$HOME/.config/hypr/scripts/caching.sh" 2>/dev/null || true
qs_ensure_cache "workspaces" 2>/dev/null || {
    RUN="${XDG_RUNTIME_DIR:-/tmp}/quickshell/workspaces"; mkdir -p "$RUN"
    QS_RUN_WORKSPACES="$RUN"
}
OUT="$QS_RUN_WORKSPACES/workspaces.json"

emit() {
    # Full snapshot from workspaces + windows, then write the bar's shape.
    niri msg --json workspaces > "$QS_RUN_WORKSPACES/ws.raw" 2>/dev/null || return
    niri msg --json windows    > "$QS_RUN_WORKSPACES/win.raw" 2>/dev/null || return
    python3 - "$OUT" "$QS_RUN_WORKSPACES" <<'PY'
import json, sys, os
out, run = sys.argv[1], sys.argv[2]
ws = json.load(open(os.path.join(run, "ws.raw")))
wins = json.load(open(os.path.join(run, "win.raw")))
cls = {}
for w in wins:
    cls.setdefault(w["workspace_id"], []).append(w.get("app_id", ""))
rows = []
for w in sorted(ws, key=lambda x: (x.get("output") or "", x["idx"])):
    state = "active" if w.get("is_focused") else ("occupied" if w.get("active_window_id") is not None else "empty")
    classes = [c for c in dict.fromkeys(filter(None, cls.get(w["id"], [])))]
    rows.append({"id": w["idx"], "state": state,
                 "tooltip": w.get("name") or "", "classes": ",".join(classes)})
json.dump(rows, open(out, "w"))
PY
}

emit
# Full state arrives on connect, then deltas; re-emit on every change.
niri msg --json event-stream | while IFS= read -r _; do emit; done
```

The dynamic-vs-static workspace mismatch is the one behavioral gap (see
`risks-and-gaps.md`): Hyprland's fixed `1..workspaceCount` pills become a
derived list, or must be expressed as niri named workspaces to keep stable
identities.
