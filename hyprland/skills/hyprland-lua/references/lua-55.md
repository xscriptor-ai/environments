# Lua 5.5 for Hyprland configs (October 2026)

Hyprland 0.55+ embeds **Lua 5.5** (CMake: `lua>=5.5,<5.6`). Reference manual: https://www.lua.org/manual/5.5/manual.html. This is NOT the 5.1 dialect used by Neovim/LuaJIT code you may know: integer division is native, `goto` exists, `bit32` is gone (use operators `<`, `>>`, `&`, `|`, `~`), `unpack` is `table.unpack`, `#` on tables works as expected.

## Language essentials you actually use

```lua
-- locals and blocks
local terminal = "kitty"           -- prefer locals; globals need explicit `global` in 5.5
global CONFIG_VERSION = 3          -- 5.5: declaring a global is explicit (typo guard)

-- tables: the only data structure
local t = { 1, 2, 3, ["key"] = true, nested = { a = 1 } }
t[#t + 1] = 4                       -- append
for i, v in ipairs(t) do end        -- array part, in order
for k, v in pairs(t) do end         -- all keys (unordered)

-- functions & closures (bind callbacks rely on this)
local function clamp(x, lo, hi) return math.max(lo, math.min(hi, x)) end
local counter = 0
local bump = function() counter = counter + 1; return counter end

-- varargs: 5.5 named vararg tables also exist ("..." with names)
local function callAll(fn, ...) fn(...) end

-- errors: raise, catch, richer errors
local ok, err = pcall(function() error({ code = "bad", msg = "nope" }) end)
if not ok then print("config error:", err.msg) end

-- string patterns (NOT regex — different engine; full RE2 regexes are for window rules)
local cmd, arg = "ratio 0.6":match("^(%S+)%s*(.*)$")
("a,b,c"):gmatch("[^,]+")

-- metatables: how hl objects implement :methods() and property access
local obj = setmetatable({}, { __index = function(_, k) return "default:" .. k end })
```

- `...` inside a table constructor packs args; `table.unpack` spreads them.
- `<const>`/`<close>` attributes exist (5.4+); 5.5 adds `global` declarations, read-only for-loop variables, `table.create` (preallocate), named vararg tables, incremental major GC, ~60% smaller large arrays, external strings.
- Numeric for with step: `for i = 0.5, 2.5, 0.5 do end`.
- Integer/float distinction: `1` vs `1.0`; `math.type(x)` tells them apart. Config values accept both where a float is expected.
- `os.execute` technically works but blocks the compositor event loop — never do it inside binds/timers; use `hl.exec_cmd`.

## Scope of the embedded environment

- `print` works and is re-routed to the Hyprland log (the `hl` global and `print` are the only injected globals; the standard libraries are available).
- `require` is customized: it loads from the config directory with optional extensions and wildcard support; each file gets its own environment/scope, so a `local` in one file is invisible in another. Use the module table pattern when sharing:
  - `lua/theme.lua`: `local M = {}; M.colors = {...}; return M`
  - `lua/monitors.lua`: `local theme = require("lua.theme")` (or `require("./lua/theme")`).
- Infinite loops/watchdog: `guardedPCall` wraps callbacks with timeouts; runaway `while true do end` gets killed and reported. Timer callbacks have generous but finite budgets.
- Values crossing into Hyprland config are validated with precise errors ("hl.config: bad type for argument ..."). Read them literally; they name the path and expected type.

## Editor support (LuaLS / lua-language-server)

1. Stubs are installed at `/usr/share/hypr/stubs/hl.meta.lua` (generated by Hyprland; updated with versions).
2. In your config dir, create `.luarc.json`:
   ```json
   {
     "runtime.version": "Lua 5.5",
     "workspace.library": ["/usr/share/hypr/stubs"],
     "diagnostics.globals": ["hl"]
   }
   ```
3. With LuaLS configured, `hl.get_active_window()` returns a typed `HL.Window` with fields (`class`, `title`, `pid`, `fullscreen_handler`, ...) and methods, so you can discover the object API from completions instead of guessing.
4. If completions look stale, the stubs track git versions — a distro Hyprland older than the stubs will suggest nonexistent fields; pin the stub file if it matters.

## Style rules that prevent most bugs

- Bind/timer callbacks: only dispatch, mutate state, and call `hl.*` APIs — never block.
- Prefer `local` everywhere; use `global` only for deliberate cross-file state.
- Wrap optional integrations in `pcall(require, "...")` so a missing file doesn't kill the config.
- Compute dynamic dispatcher arguments inside a function, not at load time (see binds in the parent skill).
- Keep one concern per file; the reload error surface is per-file, so a broken bar config can't take out your keybinds if it's a separate require with `pcall` fences where appropriate.
