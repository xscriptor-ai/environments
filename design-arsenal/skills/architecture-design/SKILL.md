# Architecture, structure and systems

Three architectures feed design work:

1. **Built** — buildings, interiors, facades, materials, light, scale.
2. **Information** — hierarchy, naming, navigation, findability.
3. **Visual** — grid, layers, rhythm, focal hierarchy.

## Reading architecture for composition

- Symmetry: monumentality, calm; center the subject.
- Repetition: pattern/rhythm; crop tight to abstract.
- Convergence: depth; place the vanishing point at a third or center.
- Frame within frame: doors/windows/arches isolate a subject.
- Scale: a human figure makes a building monumental.
- Material: concrete (heavy/calm), glass (cold/reflective), wood (warm),
  brick (rhythmic), metal (industrial).
- Light: direction, hardness, time of day; blue hour is cinematic, hard noon is
  graphic, overcast is soft/minimal.
- Abstraction: crop out ground/sky; rotate; reduce to 2-3 tones; mirror; repeat.

## Information architecture checklist

1. Inventory before ordering.
2. Use user language for labels.
3. Maximum three levels before navigation becomes guesswork.
4. Navigation visible, predictable, with an exit.
5. Search when the set is large.
6. Stable, readable URLs/filenames.
7. Metadata: title, description, license, author, date.
8. Governance: who adds, who archives, by what rule.
9. Test: can someone find an item without an explanation?

## Visual architecture

- 12-column grid; 8 px base; 3x3 for photography.
- One primary focal point, one secondary, one quiet field.
- Layers: field, midground, subject, accents, grain.
- Rhythm: repeat an interval, break it once.
- Contrast: light/dark, full/empty, straight/curved, dense/light.
- Scale: relative size creates drama; do not use one weight everywhere.

## Design-system layers

1. Reference tokens: raw values.
2. Semantic tokens: intent.
3. Component tokens: local exceptions.
4. Components/patterns: anatomy, states, accessibility, content.
5. Documentation: use, non-use, do/don't, examples.

Rules: purpose over appearance in names; design states before default; fewer
values, used consistently; document exceptions; freeze a system for a series.
